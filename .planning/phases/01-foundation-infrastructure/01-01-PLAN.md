  <action>
Create `scripts/seed-killswitch.sh`:

```bash
#!/usr/bin/env bash
# Seed system/killSwitch = { enabled: true } in Firestore (production project).
# Idempotent: re-running just re-writes the same value.
# Prereq: gcloud auth application-default login; gcloud config set project content-gen-prod
set -euo pipefail
PROJECT_ID="${PROJECT_ID:-content-gen-prod}"

# Use gcloud firestore documents because firebase CLI does not have a generic
# document-set command in current major versions. The REST API path is:
#   POST projects/$PROJECT_ID/databases/(default)/documents/system?documentId=killSwitch
# We instead use the firebase-admin via a tiny Node one-liner if firebase-tools
# does not provide it. Simplest path: gcloud firestore import is overkill. Use
# the REST endpoint directly via curl + gcloud-printed access token.

ACCESS_TOKEN="$(gcloud auth print-access-token)"
PARENT="projects/${PROJECT_ID}/databases/(default)/documents"
DOC_PATH="system/killSwitch"

# Patch (upsert) the document with field enabled=true
curl -fsS -X PATCH \
  "https://firestore.googleapis.com/v1/${PARENT}/${DOC_PATH}" \
  -H "Authorization: Bearer ${ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  --data '{"fields": {"enabled": {"booleanValue": true}}}' \
  | grep -q '"enabled"'

echo "system/killSwitch seeded with enabled=true in project ${PROJECT_ID}"
```

This script uses the Firestore REST API directly with `gcloud auth print-access-token` to avoid pulling in firebase-admin or a Node toolchain just for the seed. It is upsert-style (PATCH on a document path), so re-running flips enabled back to true (the intended dev/post-trip recovery behavior).

Note: seeding requires Firestore security rules to permit the write. Per D-28, `system/{doc}` allow write: if false in client rules — but this is server-side via the Firestore Admin API with project-owner credentials, which bypasses security rules. So this script must be run by Tim (project owner), never from a frontend.
